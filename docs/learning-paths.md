# 后端与 Agent 学习路线

我的主要方向是 **后端工程** 和 **AI Agent**。算法、数据库、网络与模型知识作为两条主线共同依赖的基础能力，在项目中按需补齐。

!!! tip "路线的使用方式"
    不追求一次学完所有名词。每一阶段都完成一个可以运行、可以解释、可以复盘的最小项目，再进入下一阶段。

## 主线一 · 后端工程

### 01 / 编程、网络与数据基础

掌握一门后端语言，理解 HTTP 请求生命周期、关系型数据库、缓存与常见数据结构。重点不是 API 数量，而是能解释数据怎样进入系统、怎样被验证、存储和返回。

| 能力 | 学习内容 | 阶段产出 |
| --- | --- | --- |
| 编程基础 | Python / Java / C++、异常处理、测试 | 一个带测试的命令行应用 |
| Web 基础 | HTTP、REST、鉴权、参数校验 | 一组可调用的 CRUD API |
| 数据存储 | MySQL、索引、事务、Redis | 带缓存和分页的查询服务 |
| 算法基础 | 哈希、栈、树、二分、复杂度 | 能解释接口中的性能瓶颈 |

### 02 / 构建可靠服务

进入日志、配置、并发、消息队列、限流和容错。为服务补齐接口文档、统一错误处理、单元测试与集成测试，并使用 Docker 固化运行环境。

推荐实践：从 [Tiny Redis Blog](https://github.com/MU-ty/tiny-redis-blog) 拆出用户、文章、缓存三个模块，记录缓存命中、数据库查询与异常路径。

### 03 / 部署、观测与架构

学习 CI/CD、反向代理、指标、Trace 和告警。能够根据流量、延迟和一致性要求做架构取舍，并写清楚“为什么这样设计”。

## 主线二 · AI Agent

### 01 / 从模型调用到工具调用

先理解 LLM/VLM 的输入输出、结构化响应与 Tool Calling，再实现一个只有单个工具、行为可验证的 Agent。此阶段重点处理参数校验、超时、重试和错误反馈。

### 02 / 上下文、记忆与知识

学习 Prompt、Skills、Context Engineering、向量检索、BM25 与 Hybrid RAG。区分短期上下文、长期记忆和外部知识库，避免把所有信息都塞进一次请求。

### 03 / Runtime、工作流与评估

把 Agent 运行过程拆成状态、任务、工作流和异步执行；再扩展 Coding Agent、Multi-Agent 与多模态能力。最后用 Trace、数据集和 Benchmark 评估质量、成本与稳定性。

## 两条主线如何汇合

Agent 应用最终仍然是一个需要可靠运行的后端系统。可以用同一个项目串联两条路线：

1. 后端提供鉴权、任务队列、数据库和文件服务。
2. Agent 负责模型调用、工具编排、记忆与知识检索。
3. 观测系统记录 Trace、耗时、Token、错误与评估结果。
4. CI/CD 将服务部署到可复现的环境，并用测试守住核心行为。

- [ ] 我为关键行为写了最小测试或评估样例。
- [ ] 我能解释当前方案的限制、成本和替代方案。
- [ ] 我完成了一个可运行、可演示、可部署的小项目。
